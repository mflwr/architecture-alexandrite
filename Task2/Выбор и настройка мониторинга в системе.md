**Мотивация внедрения мониторинга**

**Проблемы без мониторинга**
- Невозможно оперативно выявлять узкие места (например, зависание расчета стоимости в MES, блокировки БД).
- Клиенты теряют доверие из-за просрочек, а бизнес — контракты.
- Нет данных для анализа причин сбоев (потеря заказов через API, медленная работа MES).
- Реакция на проблемы происходит постфактум, после жалоб клиентов.

**Что даст мониторинг:**
- Снижение времени простоя: Быстрое обнаружение и устранение инцидентов (например, забитые очереди RabbitMQ).
- Прозрачность процессов: Понимание, на каком этапе «застревают» заказы (например, зависание статуса PRICE_CALCULATED).
- Оптимизация ресурсов: Выявление перегруженных сервисов (например, CRM при ручном подтверждении заказов).
- Предсказуемость: Прогнозирование нагрузки (рост на 100 заказов/месяц) и планирование масштабирования.

---

**Метрики для мониторинга**

--

**Для онлайн-магазина и API (RED)**

**http_requests_total**

Считать количество запросов к API (B2B/B2C).	

**http_request_duration_seconds**	

Определить задержки при расчете стоимости или создании заказа.	

**http_errors_total**	

Выявить сбои при загрузке 3D-моделей или отправке заказов.	

--

**Для MES (Четыре золотых сигнала)**

**mes_order_calculation_time**	

Контроль времени расчета стоимости (2-30 мин).	

**mes_dashboard_load_time**	

Измерить скорость загрузки дашборда операторов.	

**mes_order_status_transitions**	

Отслеживать «зависшие» заказы (например, в PRICE_CALCULATED).	

**mes_errors_total**	

Ловить ошибки при изменении статусов (например, переход из SUBMITTED в CLOSED).

--

**Для инфраструктуры (USE)**

**cpu_usage**	

Предотвратить перегрузку серверов MES/CRM.	

**rabbitmq_queue_messages**	

Обнаружить накопление сообщений (например, при сбое интеграции CRM-MES).	

**rabbitmq_dlq_messages**	

Мониторинг dead letter сообщений.	


**db_active_connections**	

Выявить утечки соединений в PostgreSQL 

--

**Для RabbitMQ (USE + RED)**

		
**rabbitmq_message_publish_rate**	

Контролировать нагрузку на очередь (например, при массовом создании заказов).	routing_key (order.created, status.updated)

**rabbitmq_consumer_lag**

Обнаружить задержки обработки сообщений (например, подтверждение заказа в CRM).	consumer_group (CRM, MES)

**Дополнительные метрики**

**Бизнес-метрики**

- orders_created_total (по типам: B2C, B2B).
- order_status_duration (время в каждом статусе, например, от SUBMITTED до CLOSED).

**SLA/SLO:**

- slo_price_calculation_time (например, 95% запросов ≤ 5 мин).
- slo_api_availability (99.9% uptime для B2B-партнеров).

**Инструменты**
- Prometheus 
- Grafana
- Alertmanager

**Интеграции**
- RabbitMQ Exporter для мониторинга очередей
- PostgreSQL Exporter для БД
- Blackbox Exporter для проверки доступности API

**Обоснование для бизнеса**

**Сокращение потерь** 

Каждый потерянный контракт из-за сбоев — это упущенная выручка. Мониторинг позволит снизить такие риски на 30-50%.

**Ускорение реакций**

Среднее время устранения инцидентов сократится с часов до минут (например, перегрузка MES будет детектироваться автоматически).

**Поддержка роста**

Система масштабируется на 200% (сейчас +100 заказов/месяц), и мониторинг поможет планировать ресурсы.

Пример:если метрика mes_order_calculation_time покажет, что 20% расчетов занимают >15 мин, можно оптимизировать алгоритм или выделить отдельные воркеры для сложных моделей.**
